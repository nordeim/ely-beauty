## Environment shadowing (sandbox trap)

Any `DATABASE_URL` already present in the process environment (shell export, CI inject, parent `.env`) **wins over the repo `.env`** — Prisma never overrides existing process env. Symptom: `db/custom.db` never appears at the repo root, or rows survive "fresh" reseeds (the file being written is elsewhere). Diagnose with `node -e "console.log(process.env.DATABASE_URL)"` from the repo root. If the shadowed path differs, converge them (symlink) or unset before running DB commands.

## Build-config loss (the operator's run-87 312-error wall — resilience contract)

The operator's checkout tree once lost `tsconfig.json` + `postcss.config.mjs` (the only build-critical root configs untouched since the 2026-10-12 initial migration; the pinned contract is `tests/unit/build-config-resilience.test.ts`), and `npm run build` died with 312 module-not-found errors (311 `@/` aliases + `tw-animate-css`) plus 15 `@apply`/`@utility` "Unknown at rule" warnings — no tsconfig → no `@/*` paths for Turbopack and the build's type-check; no postcss config → `@tailwindcss/postcss` never registers → the CSS pipeline falls to raw PostCSS. Three layers now make the build survive that loss class (pinned by `tests/unit/build-config-resilience.test.ts`):

1. `next.config.ts` carries the alias itself (`turbopack.resolveAlias: { "@/*": "./src/*" }` — the identical mapping to tsconfig paths), so Turbopack compilation never depends on tsconfig.json surviving the checkout.
2. `scripts/ensure-build-configs.mjs` embeds the five long-untouched configs (`tsconfig.json`, `postcss.config.mjs`, `vitest.config.ts`, `tsconfig.tests.json`, `eslint.config.mjs`) in its `CONFIG_FALLBACKS` registry and restores any that are missing or empty — it NEVER overwrites existing content.
3. Every gated npm script (`build`, `dev`, `lint`, `test`, `test:e2e`, `typecheck`, `typecheck:tests`) runs that bootstrap first (~10 ms, silent when nothing is missing).

**Maintenance rule:** when editing any registered config, update its `CONFIG_FALLBACKS` copy in the same commit — the unit pin fails the suite on drift. Verified end-to-end on the poison trees (fresh install, each config deleted, the operator's exact both-missing tree): 4/4 builds green, the restored tsconfig byte-identical, the standalone server's CSS carrying compiled `@apply` output.

## DATABASE_URL contract (pinned by tests/unit/db-path.test.ts)

`.env` carries `DATABASE_URL="file:../db/custom.db"`; `db/` lives at the repo root (git-ignored). A **relative** `file:` URL resolves against `prisma/schema.prisma` — at runtime via `src/lib/db-path.ts` AND for the seed (S77-6: `prisma/seed.ts` passes `datasourceUrl: resolveProcessDatabaseUrl()`; `prisma db push` still follows the shell env, so converge or unset shadowed `DATABASE_URL`s before CLI runs) — so `next dev`, `next build`, the standalone server and `db:seed` all open ONE file at `<repo>/db/custom.db` regardless of CWD. Absolute `file:` URLs and non-SQLite URLs pass through untouched. ## Tailwind v4 trap log (violating these breaks production renders)

1. **Never JS-toggle a display utility.** v4 changed display-utility generation order, so toggling the `hidden` class on an element that also carries `flex`/`block` is unreliable (tailwindlabs/tailwindcss#15884, #18653; preflight's `[hidden]` is `!important`). Overlays/menus mount conditionally via React state or use transform/opacity. Pinned by `tests/e2e/mobile-navigation.spec.ts`.
2. **Theme colors are FULL `hsl()` values** in `@theme inline` — bare `H S% L%` triplets silently resolve to transparent.
3. **`hover:` is un-gated**: `@custom-variant hover (&:hover)` in `globals.css` restores v3 semantics so touch devices still render hover styles.
4. **`--shadow-sm` is pinned to v3 geometry**; the radius scale is pinned to the reference's measured px (ElyBeauty: sharp 4px `--radius`). Don't "upgrade" these pins.
5. Config is CSS-first (`@theme` in `src/app/globals.css`) — there is no `tailwind.config.js` and none should be added.
6. **`@apply` cannot reference classes declared in `@layer utilities`** (run-72 trap): `@apply eyebrow-label` from a plain `@layer utilities { .eyebrow-label {…} }` fails the build with "Cannot apply unknown utility class". Apply-able custom classes must be declared with `@utility` (see `eyebrow-label` / `link-cta` in `globals.css`).
7. **The candidate scan reads PROSE (run-76 trap, S76-0)**: Tailwind v4's automatic source detection scans EVERY non-gitignored text file — .md docs included. A class-like string in a session log (`md:aspect-[3:1]`, colon-form, in four doc files) compiled to `aspect-ratio:3:1` (invalid CSS) and broke the CLEAN production build while a warm Turbopack cache masked it (run-75 shipped a false-green). The `@source not` guard in globals.css excludes docs/, skills/ (operator contract), tests/, scripts/, `**/*.md`, `**/*.mdx` — pinned by `tests/unit/tailwind-scan-guard.test.ts`. Never remove it; keep prose out of the CSS graph. Related environmental lesson: a stale `node_modules/.cache/jiti` breaks Turbopack's next/font import map ("next/font/google queries have exactly one entry") — clear `node_modules/.cache` + `.next` before suspecting code.
7. `reactStrictMode: false` in `next.config.ts` is deliberate: StrictMode's dev double-invocation produces double `useEffect` fetches in the cart-drawer/cart-summary islands that race the per-line pending locks. Re-enable only together with a re-audit of every fetch effect.
8. The hero carousel pauses auto-rotation on hover/focus and under `prefers-reduced-motion` (WCAG 2.2.2) via `useSyncExternalStore` — do NOT replace that with a set-state-in-effect `matchMedia` listener (lint's `react-hooks/set-state-in-effect` rejects it, correctly).

## CSP nonce trap (Next 16 + `src/proxy.ts`)

The proxy stamps a **per-request nonce** CSP on every response; Next applies the request-header nonce to the scripts it renders. A **prerendered/static page bakes no (or build-time) nonces** → the browser silently refuses its scripts → hydration never happens, with zero console errors. Symptom: a page that loads, paints, but never hydrates. Fix: make the route render per-request (`await connection()` in the layout — `force-dynamic` alone did NOT de-prerender in Next 16.4). The `(auth)` layout carries this fix with a comment; don't remove it. Pinned by the auth e2e specs.

## Server-only module graph trap (Turbopack panic)

Shared modules that CLIENT islands import (`src/lib/validation.ts`, `src/lib/format.ts`, `src/lib/money.ts`, …) must never re-export from (or import) server-only modules — anything reaching `src/lib/db.ts` pulls `@prisma/client` → `node:fs` into a browser chunk and Turbopack PANICS at build with `the chunking context (unknown) does not support external modules (request: node:fs)` (session-19: a `export { couponLabel } from "@/lib/coupons"` re-export in validation.ts killed every admin page's build with a panic pointing at an unrelated route). Client-safe libs define their own pure helpers (or live in a module with zero server imports); server pages import the server-only helper directly from its home module. Symptom signature: the panic names a route that does not import the new code — trace the CLIENT graph, not the route.
